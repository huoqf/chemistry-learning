# 代码格式策略（FORMATTING_POLICY）

> 对应符合性审查报告 **G10「prettier 已安装但无任何调用，代码格式无门禁」**。
> 结论先行：**本项目不把 prettier 作为格式门禁**，改用 `scripts/check-code-style.mjs` 兜住
> 「可机械判定、且不破坏手工排版」的三条规则。**禁止执行全量 `prettier --write`。**

---

## 一、项目实际的排版风格

| 项 | 约定 |
|---|---|
| 分号 | **不写**（语句末尾一律省略分号） |
| 引号 | 单引号 `'`；JSX 属性同样用单引号 |
| 缩进 | 2 空格，禁止 Tab |
| 行宽 | 约 100 字符，但不强制换行 |
| 对象字面量 | **允许并鼓励列对齐**（`sm:    '4px'`），便于纵向扫读 |
| 行尾注释 | **允许并与相邻行对齐** |
| 多行 SVG `d` 模板字面量 | 允许在字符串内用「空格 + 换行」分隔 `M/L/C` 指令 |

**为什么强调「列对齐」**：`src/theme/*.ts`、`src/data/**` 等大量数据文件使用
`key:    value,` 的纵向对齐写法，是刻意为之的可读性设计。任何自动格式化工具
一旦抹平这些空格，会显著降低这批文件的扫读效率。

---

## 二、实测：prettier 为什么不能作为门禁

在 `src/**/*.{ts,tsx}` 上实测（prettier 3.9.5）：

| 配置 | 不通过文件数 |
|---|---|
| `semi: true`（`.prettierrc` 原值） | **634** |
| `semi: false`（改为与代码一致后） | **543** |

即：把 `semi` 改对只消除约 91 个文件的分歧，**剩余 543 个文件的差异主要来自
prettier 会打散列对齐**——这不是「代码写错了」，而是「工具与既定风格不兼容」。

示例（`src/theme/radius.ts`）：

```ts
// 现状（列对齐，可读性好）
none:  '0px',
sm:    '4px',
base:  '6px',

// prettier 输出（对齐被抹平）
none: '0px',
sm: '4px',
base: '6px',
```

因此：
- 若执行全量 `prettier --write`，将产生 **500+ 文件的噪声级 diff**，且**降低**可读性；
- 若在 CI 加 `prettier --check`，将**永久红灯**，等同于「训练所有人忽略 CI 信号」
  （这正是审查报告对 G3b 的批评）。

**决策：不采用 prettier 作为门禁。** `.prettierrc` 保留但仅作文档性声明
（`semi` 已修正为 `false`，与代码一致），`prettier` 依赖保留但**不接入任何脚本/钩子**。

---

## 三、实际启用的格式门禁：`scripts/check-code-style.mjs`

只做三条可机械判定、且不会破坏手工排版的检查：

1. **行尾多余空白** —— 提交 diff 噪声、编辑器告警的常见来源；
2. **文件末尾缺少换行** —— POSIX 文本文件约定；
3. **同一文件内混用 CRLF 与 LF** —— 跨平台 diff 噪声来源。

明确**不**检查（有意为之）：

- 不强制全文件统一为 LF 或 CRLF —— 会产生整文件级 diff，收益低于风险，只禁止「同文件内混用」；
- 不检查文件末尾多余空行 —— 纯审美偏好；
- 不做任何重排 —— 重排即破坏列对齐。

运行方式：

```bash
npm run check:code-style     # 单独运行
npm run lint                 # 已包含（CI 与 lefthook pre-commit 均调用 npm run lint）
```

豁免机制与 `check-no-marker.mjs` 一致：`ALLOWLIST` 条目必须带 `reason` 与 `targetDate`，
到期后脚本报错提醒清理。当前唯一豁免为 `KippApparatus.tsx` 的 4 行 SVG `d`
模板字面量（其中的空格是字符串内容的一部分）。

---

## 四、给贡献者 / AI 的硬约束

1. **禁止** 运行 `npx prettier --write` / `--check` 并据此改代码；
2. **禁止** 为「让 prettier 通过」而抹平列对齐或批量加/删分号；
3. 提交前跑 `npm run lint` 与 `npm run test:run`；
4. 如果未来确需引入自动格式化，必须先解决「列对齐」这一冲突
   （例如改用 `prettier-plugin-*` 排序/对齐插件，或接受一次性全量重排），
   并经仓库所有者确认后再执行——**不可默认执行**。
