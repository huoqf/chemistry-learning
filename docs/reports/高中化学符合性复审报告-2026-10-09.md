## 三、P0 清单（结论性错误 · 13 条 · 全部经逐行复验）

> 判定标准：会直接让学生形成错误化学结论，或显示与自身文字互斥的错误数值。

### P0-1 ✅ 母题一：过量碱区 HA/A⁻ 浓度公式上下颠倒
- **位置**：`src/features/titration-balance/hooks/useTitrationChemistry.ts:71`
- **原文**：`cHA = (Ka * cATotal) / (cH + Ka)`
- **问题**：`Ka/(c(H⁺)+Ka)` 是 **A⁻ 的分布分数**，被赋给了 `cHA`。HA 的分布分数应为 `c(H⁺)/(c(H⁺)+Ka)`。
- **验算**（pKa=4.75、c0=0.1、V₀=20、vRatio=2.0）：cOH=3.33×10⁻²，cH=3.0×10⁻¹³，cATotal=3.33×10⁻² → 代码得 **c(HA)=0.0333、c(A⁻)=0**；真实应为 **c(A⁻)≈0.0333、c(HA)≈1.7×10⁻⁸**。
- **连带后果**：右屏 `:121` 文案写 `c(Na⁺) > c(A⁻) > c(OH⁻) > c(HA) > c(H⁺)`，与同屏数值（A⁻=0）**直接互斥**。
- **修复**：`cHA = (cH * cATotal) / (cH + Ka); cA = cATotal - cHA`。

### P0-2 ✅ 母题一：半中和点离子排序把 c(OH⁻)/c(H⁺) 写反，且与自身解释矛盾
- **位置**：`useTitrationChemistry.ts:105`
- **原文**：`'c(Na⁺) > c(A⁻) > c(HA) > c(OH⁻) > c(H⁺)'`，同行解释却写"溶液呈弱酸性"
- **问题**：半中和点 pH=pKa=4.75（酸性），必有 c(H⁺) > c(OH⁻)（实为 1.78×10⁻⁵ vs 5.62×10⁻¹⁰）；由电荷守恒酸性时 c(A⁻) > c(Na⁺)，文案方向亦反；且代码 `:58` 取 `cA = cNa`、`cHA = cATotal - cA` 反而得 c(HA) 略大于 c(A⁻)，三重冲突。
- **正确排序**：`c(A⁻) > c(Na⁺) > c(HA) > c(H⁺) > c(OH⁻)`
- **修复**：按 pH 与 7 的关系分支输出 H⁺/OH⁻ 次序（或直接由计算值动态排序），并修正 Na⁺/A⁻ 方向。

### P0-3 ✅ 母题一：强酸滴定弱碱的兜底分支排序同样写反
- **位置**：`useTitrationChemistry.ts:210`
- **原文**：`'c(Cl⁻) > c(BH⁺) > c(H⁺) > c(OH⁻)'`（该 else 覆盖 vRatio∈[0,0.45) 与 (0.55,0.95)）
- **验算**：vRatio=0.2 时弱碱大量剩余，pH≈9.85，c(OH⁻)=7.1×10⁻⁵ ≫ c(H⁺)=1.4×10⁻¹⁰，文案方向完全相反。
- **修复**：同 P0-2，按酸碱性强弱分支。（`:194`、`:202` 两个分支本身正确。）

### P0-4 ✅ 母题九：SO₃ 分支密度换算漏 ×1000，教学结论讲反
- **位置**：`src/features/avogadro-constant/hooks/avogadroStateStructureCalculations.ts:20`
- **原文**：`const actualMoles = unit === 'L' ? (val * 1.92) / 80 : molesGiven`
- **问题**：密度 1.92 的单位是 **g/cm³（=1920 g/L）**，`val` 单位是 **L**，缺 ×1000。
- **验算**：22.4 L×1.92÷80 = **0.5376 mol**（代码）；正确为 22.4×1920÷80 = **537.6 mol**，与 `:35` 文案"约 537 N_A"一致。
- **连带后果**：中屏"真实值 vs 错解"对比图会画出 **真实值(0.54) < 错解(1.0)**，把"固态 SO₃ 物质的量远大于 1 mol"的结论**完全讲反**。同文件 H₂O（`:60`）、CH₃OH（`:100`）、CCl₄（`:176`）均已 ×1000，唯 SO₃ 漏乘。
- **修复**：`(val * 1920) / 80`。

### P0-5 ✅ 实验二：Li₂CO₃ 反常溶解度曲线数值放大 10 倍
- **位置**：`src/features/industrial-flow/hooks/useIndustrialFlowChemistry.ts:564`
- **原文**：`const mainSol = Math.round((1.54 - 0.0082 * t) * 100) / 10`（同行注释：0℃ 1.54 g、100℃ 0.72 g）
- **验算**：t=0 → round(154)/10 = **15.4**（应为 1.54）；t=100 → 7.2（应为 0.72）。同段 `:566`、`:569` 用的是 `*10`，量纲写法自相矛盾。
- **修复**：改为 `Math.round((1.54 - 0.0082 * t) * 10) / 10`。

### P0-6 ✅ 实验一：乙炔"被 NaOH 吸收"系事实错误，且与自身"碱石灰可用"直接冲突
- **位置**：`src/features/gas-chain/data/gasMatrixItems.ts:213`（purifyPrinciple）、`:215`（incompatibleDrying）
- **原文**：`'严禁用 NaOH——NaOH 会与弱酸性的 C₂H₂ 反应导致目标气体损失'` / `'NaOH 溶液 (C₂H₂ 具有弱酸性，NaOH 会将其吸收)'`
- **化学依据**：乙炔端基氢 pKa≈25，远弱于水，`HC≡CH + OH⁻ ⇌ HC≡C⁻ + H₂O` 的 K≈5×10⁻¹⁰，**几乎不发生**；乙炔需 NaNH₂/熔融 Na 才能去质子化。已联网核实多方口径：**乙炔不与 NaOH/KOH 反应**。
- **自相矛盾**：同一项 `:214` 的 `dryReagents` 明确列出 **`碱石灰`（CaO+NaOH）** 为可用干燥剂；`gasDecisionModels.ts:272` 亦把 C₂H₂ 列入碱石灰适用气体——若"NaOH 吸收乙炔"成立，碱石灰同样会破坏它。
- **修复**：删除该理由。正确理由应为"CuSO₄ 以难溶 CuS/磷化铜**同时**除去 H₂S 与 PH₃，而 NaOH 只能吸收 H₂S、除不掉 PH₃，故首选 CuSO₄"。

### P0-7 ✅ 专题三：硝基还原方程式未配平
- **位置**：`src/features/organic-functional-matrix/constants.ts:385`
- **原文**：`'铁粉/稀盐酸 (Fe + 6HCl + Ar-NO₂ → Ar-NH₃Cl + 3FeCl₂ + 2H₂O，再加碱释放芳香胺)'`
- **问题**：左端 `Fe` 系数为 1，右端 `3FeCl₂` 含 3 个 Fe，**Fe 原子不守恒**；且产物若为盐酸盐 `Ar-NH₃Cl`，HCl 应为 7 而非 6。
- **修复**：`3Fe + 6HCl + Ar-NO₂ = Ar-NH₂ + 3FeCl₂ + 2H₂O`。

### P0-8 ✅ 母题八：逐级电离能算法对默认元素（碳）输出错误结论
- **位置**：`src/features/element-periodic-property/hooks/useElementPeriodicChemistry.ts:131-148`
- **原文**：无条件取 I₁~I₄ 内相邻比值最大者，即断言"发生剧烈突跃（倍率 X 倍），该元素最外层价电子数为 X"
- **验算**（默认元素 **碳**，`:selectedAtomicNumber: 6`；`periodicData.ts` C 的 stepIonization=[1086, 2353, 4620, 6223]）：比值 2.17 / 1.96 / 1.35 → maxJumpIndex=1 → 页面输出 **"该元素最外层价电子数为 1"**（碳应为 **4**，真正的大突跃在 I₄→I₅≈43600，不在数据窗口内）。
- **额外矛盾**：2.2 倍根本不是"剧烈突跃"——右屏 `ElementPeriodicRightPanel.tsx:144` 自定标准为"倍数 >4~5 倍才是跨层标志"，算法与自定标准互相打架。N/O/F 同样被误判为 1。
- **修复**：设比值阈值（<4 倍不判突跃），数据不足时输出"数据不足以判定"；d 区元素显式提示"逐级电离能不能简单用于过渡元素"。

### P0-9 ✅ 母题二：中屏 O₂ 体积取了错误变量，恒显示 0 L
- **位置**：`src/features/electrochemical-twin/components/ElectrochemicalTwinCenterView.tsx:626`
- **原文**：`V(O₂) = {quantResult.gasVolumeRight} L`
- **问题**：模式 3（电解水/阳极析氧）中 O₂ 在**阳极（左）**，hook 设 `gasVolumeLeft = n(e⁻)/4×22.4`、`gasVolumeRight = 0`（`useElectrochemicalTwin.ts:66-67`）。取 `gasVolumeRight` → 画面恒显示 **V(O₂)=0 L**（右屏 `:239` 用的是正确变量）。
- **修复**：改为 `gasVolumeLeft`。

### P0-10 ✅ 母题二：把 NaOH 称为"纯碱"
- **位置**：`src/features/electrochemical-twin/components/ElectrochemicalTwinRightPanel.tsx:368`
- **原文**：`'…阳极析出的 Cl₂ 会与阴极生成的 NaOH 反应生成 NaClO，导致纯碱减产。'`
- **问题**：**纯碱 = Na₂CO₃**；此处产物是 **NaOH（烧碱/火碱/苛性钠）**。属高考高频易错命名，出现在"警示"条目里尤其有害。
- **修复**：改为"烧碱（NaOH）"。

### P0-11 ✅ 母题五：XeF₂ / XeF₄ 右屏显示"（无孤对挤压）"
- **位置**：`src/features/vsepr-hybrid-3d/components/VseprRightPanel.tsx:149` + `hooks/useVseprChemistry.ts:50-51`
- **原文**：`{actualAngle !== theoreticalAngle ? '(理想:…)' : '(无孤对挤压)'}`
- **问题**：`vseprData.ts` 中 XeF₂（`lonePairs: 3`、theoretical=actual=180）、XeF₄（`lonePairs: 2`、theoretical=actual=90）因两值相等而渲染出 **"（无孤对挤压）"**——与同页明写的"3 对孤对占据赤道面/2 对孤对占轴向"直接矛盾；hook 的通用文案还会生成"含 3 对孤电子对…将键角压缩至 180°"这类**语义颠倒**的句子。
- **修复**：判定条件改为 `lonePairs === 0`；对"分子几何由孤对决定"的分子（XeF₂/XeF₄）改述为"孤对占据赤道/轴向，使分子几何不再是理想电子域几何"。

### P0-12 ✅ 母题四：c-t 浓度图违反化学计量数（2NO₂⇌N₂O₄ 按 1:1 变化）
- **位置**：`src/features/reaction-principle/nexus/hooks/useReactionPrincipleChemistry.ts:281-288`
- **原文**：`cReactant -= 0.05 * (1 - decay)`；`cProduct += 0.05 * (1 - decay)`
- **问题**：正向 2NO₂ ⇌ N₂O₄ 中反应物减 2 份、产物只增 1 份。代码令二者**等量反向变化**，违反计量数与 N 原子守恒（初始 c(NO₂)=2.0、c(N₂O₄)=1.0，N 当量由 4.0 漂移到 3.9）。
- **说明**：同仓库 `data/quantities/reaction-principle/leChatelier.ts` 的守恒建模是**正确**的（见第九部分），本模块未复用。
- **修复**：`ΔcProduct = |ΔcReactant| / 2`，或复用 leChatelier 的守恒解。

### P0-13 ✅ 母题八：激发态切换对默认元素（碳）毫无变化
- **位置**：`src/features/element-periodic-property/hooks/useElementPeriodicChemistry.ts:74`（移除）与 `:94`（安置）
- **原文**：`:74` 从 `2s`（非 p 区）或 `2px`（p 区）扣 1 个电子；`:94` `res.find(b => b.electrons.length === 0)` 把电子放进**数组中第一个空方框**
- **问题**：对 B/C/N 等 2p 仅单占的元素（2px 恰为 1 个电子），移除后 **2px 变成第一个空方框**，电子被立刻放回**同一轨道** → 基态与激发态**完全相同**。默认元素正是碳，学生点"激发态"看不到任何变化。
- **附**：对 s/d 区元素则从 **2s 内层**跃迁（对 Mn 是 2s→4p），与"最外层价电子跃迁"的教材表述不符；只读复验中未发现"电子总数丢失"（该说法不成立，特此更正）。
- **修复**：激发源改为**最外层已占据轨道**（如 Na 3s→3p），目标轨道需从已占据轨道之后的更高能级中选取，并加 `电子总数 === Z` 断言。
